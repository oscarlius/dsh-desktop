# 有界任务恢复

公司插件在 Harness 0.2.2-rc.1 的公开 hook 上提供默认启用的 `agentContractGuard`。它补充现有同参循环保护，不修改上游代码或已记录的工具实参。

- 工具最终结果为 `INVALID_ARGS` 时，保留失败记录；前两次提供修正上下文，第三次以 hook 原因停止。本轮累计计数不因中途用户消息而重置。
- 当前可见 schema 明确允许省略 `sandbox_permissions`、且不接受 `use_default` 时，提示模型省略该字段以沿用现有策略。不自动提高权限、填入业务参数或重放工具。
- 普通文本结束时，若本轮仍有未修复的参数错误或 `todo_write` 成功结果中的未完成待办，最多插入一次继续提醒。下一次仍未处理，则记录 `aborted/hook` 和未完成原因，不把它表示为成功验收。
- 主 Agent 和子 Agent 按对象和 turn 分别计数；下一轮重新开始。日志记录提示的生产者为 `p7-agent-contract-guard`，不会伪装成用户消息。
- 用户取消、明确的开头停用指令、权限拒绝、其他工具错误、`concludesTurn` 人工交互、令牌耗尽，以及已排队的新消息不会被此机制自动重启。

关闭方式：公司插件配置 `agentContractGuard: false`。当前实现和验证目标为 0.2.2-rc.1；旧版缺少 `tools/result` 事件时不具备完整恢复能力。

## 验证与限制

`tests/agent-contract-guard-loop.spec.ts` 使用真实 Cordis、AgentLoop、NativeExecutor、工具 schema 校验和固定 LLM 输出，覆盖这次非法 enum → 语言纠正 → 文字提前结束 → 修正调用的轨迹，并验证次数、取消、权限、令牌、主子 Agent 和新 turn 边界。测试不调用模型、GPU、文件修改工具或生产服务。

本机制只识别可观察的未完成证据。没有创建待办且没有结构化参数错误的任务不会被强制继续；它也不判断代码或业务结果是否正确。同名工具的成功调用清除该工具的参数错误标记，无法证明业务目标已达成。文本停止识别是有限的便捷补充；原生取消信号是可靠停止方式。模型仍可能需要真实用户信息或授权。

尚未完成安装包、GUI 和真实模型验收；本地测试通过不代表已经部署。
